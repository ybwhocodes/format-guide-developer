# Standar Database Supabase

## Cakupan

Supabase diperlakukan sebagai PostgreSQL terkelola dengan Auth, Storage, API exposure, Realtime, dan Edge Functions. Ikuti `PostgreSQL/postgresql-database-standard.md` lebih dulu, lalu aturan platform ini.

## Project dan schema

- Satu project memiliki tujuan, environment, owner, dan kebijakan biaya yang jelas. Pisahkan development, staging, dan production.
- Schema aplikasi dipisahkan dari `auth`, `storage`, dan schema internal Supabase. Jangan mengubah tabel internal platform secara langsung.
- Tabel publik yang dapat diakses client harus memiliki RLS. Default exposure baru harus ditolak sampai policy dan API contract direview.
- Gunakan migration sebagai sumber kebenaran schema. Perubahan dashboard yang tidak diekspor menjadi migration dianggap drift.

## RLS wajib

- Aktifkan RLS pada setiap tabel yang terekspos melalui Data API atau client SDK.
- Policy membaca, insert, update, dan delete ditulis terpisah bila kebutuhan akses berbeda.
- Gunakan `auth.uid()` dan klaim JWT yang relevan dengan predicate ownership/tenant. Tambahkan `WITH CHECK` untuk membatasi data yang boleh ditulis.
- Uji anonymous, authenticated, user lain, tenant lain, dan service role. Service role melewati RLS, jadi hanya boleh berada di server yang dipercaya.
- Jangan memakai `using (true)` untuk data privat. Jika data publik, dokumentasikan klasifikasinya dan batasi kolom sensitif.

## Auth

- Gunakan user ID Auth sebagai foreign key dengan perilaku delete yang disengaja.
- Profile application berada di tabel aplikasi sendiri, bukan modifikasi schema Auth.
- Redirect URL, provider, session lifetime, reset password, email confirmation, dan rate limit dikendalikan per environment.
- Jangan mengirim service role key ke browser. Anon key bukan pengganti RLS.

## Storage

- Bucket diklasifikasikan public/private sesuai kebutuhan bisnis. Default private untuk dokumen pengguna.
- Path file memiliki ownership dan aturan naming yang stabil. Policy `storage.objects` membatasi folder, user, tenant, MIME type, dan operasi.
- Validasi ukuran, extension, content type, filename, dan antivirus/inspection bila risiko data membutuhkan.
- Simpan metadata file penting di tabel aplikasi, bukan mengandalkan nama object saja. Signed URL memiliki expiry pendek dan scope jelas.

## API dan Realtime

- Expose hanya schema, tabel, view, dan function yang memang menjadi contract client. Hindari membuka tabel internal atau kolom sensitif.
- View dan function yang diekspos direview untuk privilege, RLS, search path, dan kebocoran data.
- Realtime channel dibatasi berdasarkan authorization dan kebutuhan. Jangan mengirim event berisi PII tanpa alasan.
- API contract tetap mengatur pagination, error, idempotency, dan versioning; autogenerated API bukan alasan mengabaikannya.

## Edge Functions dan secrets

- Edge Functions memvalidasi input, autentikasi, otorisasi, timeout, retry, dan response error.
- Secret disimpan di Supabase secrets atau secret manager yang disetujui, bukan source, migration, log, atau client bundle.
- Service role hanya dipakai pada jalur server yang memerlukan bypass RLS dan diaudit.
- Network call eksternal berada di luar transaction database bila memungkinkan. Gunakan idempotency untuk webhook dan retry.

## Migration, backup, dan operasi

- Migration diberi nama berurutan, kecil, reviewable, dan kompatibel dengan deploy bertahap.
- Seed data dipisahkan dari migration schema dan aman dijalankan ulang.
- Lakukan `db diff`/review drift sesuai tooling proyek sebelum deploy.
- Aktifkan backup sesuai plan. Pastikan PITR, retensi, restore test, export, dan dependency extension sesuai kebutuhan plan dan RPO/RTO.
- Pantau database size, connections, query latency, errors, API exposure, Auth failures, Storage failures, Edge Function logs, dan RLS regressions.

## Checklist Supabase

- [ ] Environment project terpisah dan owner jelas.
- [ ] Migration menjadi sumber kebenaran; tidak ada drift tak terdokumentasi.
- [ ] RLS aktif dan diuji untuk setiap tabel yang terekspos.
- [ ] Auth, Storage policy, API exposure, Realtime, dan Edge Functions direview.
- [ ] Anon/service key, secrets, backup, restore test, dan monitoring aman.
